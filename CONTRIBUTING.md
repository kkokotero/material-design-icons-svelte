# Contributing to material-design-icons-svelte

Thank you for considering contributing to `material-design-icons-svelte`.

This library generates tree-shakeable Svelte 5 components from Google's official Material Symbols / Material Design Icons SVGs. Contributions that improve the generator, documentation, component ergonomics, and API clarity are welcome.

## Ways To Contribute

- reporting bugs in generated components or missing icons
- improving documentation, README, or examples
- improving the icon generation scripts (`scripts/generate-dist.mjs`, `scripts/generate-data.mjs`, `scripts/update-icon-metadata.mjs`)
- proposing API improvements aligned with the project's design goals

## Before You Start

For small fixes, open a pull request directly.

For larger changes, open an issue first so we can align on scope, API design, and compatibility impact.

Changes that should usually be discussed first:

- new public exports or subpath imports
- changes to the generated component template
- changes to how icons are named, organized, or exported
- adding runtime dependencies
- breaking changes to the public API

## Local Setup

```bash
npm install
```

Useful commands during development:

```bash
npm run dev      # regenerates src/lib/icons, then runs the demo site
npm run build    # regenerates src/lib/icons, builds the demo site, runs publint
npm run build:lib # regenerates dist/ (the publishable library)
npm run check    # svelte-check
npm run lint     # biome check
npm run format   # biome format
```

The library output (`dist/`) and the demo site data (`src/lib/icons`) are generated by separate scripts that share helpers in `scripts/shared.mjs`:

- `npm run generate:dist` executes `scripts/generate-dist.mjs`, which reads SVGs from `@material-design-icons/svg` and writes the publish-ready package directly into `dist/`. Generation is incremental per style: existing variants in `dist/` are skipped. Use `node scripts/generate-dist.mjs --force` for a full regeneration.
- `npm run generate:data` executes `scripts/generate-data.mjs`, which always regenerates the SVG data used by the demo site into `src/lib/icons/data/` plus `src/lib/icons/metadata.ts` and `src/lib/icons/index.ts`. It runs automatically before `npm run dev` and `npm run build`.
- `npm run update:metadata` refreshes the vendored icon categories/tags from Google Fonts into `scripts/data/icons-metadata.json` (ignored via `.gitignore`). Run it when the upstream icon set changes.

## Generated Code

Everything under `dist/` is auto-generated. Do not edit those files manually — changes will be overwritten on the next generation. To change the output, modify the templates inside the generator script.

## Contribution Guidelines

- Use English for code, comments, issues, and pull requests.
- Keep the public API minimal and predictable.
- Zero runtime dependencies is a hard constraint.
- Avoid breaking changes unless clearly justified and documented.
- Update documentation when public behavior or output changes.
- Preserve existing naming conventions and import patterns.

## Code Style

- Use strict TypeScript with explicit types on public APIs.
- Prefer readable, explicit code over clever abstractions.
- Keep the generator focused: file discovery, naming, templating, and writing are separate concerns.
- Preserve the existing project structure: `scripts/`, `dist/{style}/`, `src/routes/`.

## Pull Request Checklist

Before opening a PR, make sure:

- `npm run check` passes
- `npm run lint` passes
- generated output is reproducible with `node scripts/generate-dist.mjs --force`
- docs are updated when public API or behavior changes
- breaking changes or migration notes are called out clearly

## Commit Messages

Use [Conventional Commits](https://www.conventionalcommits.org/):

```
feat: add support for Material Symbols variable weights
fix: escape special characters in generated icon titles
perf: increase generation concurrency
docs: document two-tone style usage
```

## Review Expectations

Reviews focus on:

- correctness of the generator and generated components
- API clarity and consistency
- backward compatibility
- documentation quality
- maintainability

Feedback is meant to improve the project. Questions, iterations, and design discussion are welcome.

## Need Help?

If you are unsure whether an idea fits `material-design-icons-svelte`, open an issue and describe:

- the use case
- the proposed API or behavior
- alternatives you considered
- compatibility concerns
